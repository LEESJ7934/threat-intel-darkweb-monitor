# 메타데이터 기반 Incident Response Playbook

프로젝트용 대응 설계 예제입니다. 실제 침해 확정, 기관 신고 의무 판단, 인증 적합성 판단을
자동 수행하는 절차가 아닙니다. 담당자와 조직 정책에 따라 사례별로 검토합니다.

| 단계 | 담당자 행동 | 남길 최소 기록 |
|---|---|---|
| 1. 탐지 | 새 event/history/alert를 확인하고 동일 event_key·document_id인지 대조 | 사건 참조값, 최초/최근 관찰 시각, 발견 경로 |
| 2. 분류 | Day 10 위험도와 이유를 참고하되 확정된 침해와 게시자 주장을 구분 | 기존 risk_level, 검토 우선순위, 담당자 |
| 3. 검증 | 회사명/도메인/국가의 연관성, 시각, metadata 변경을 허용된 자료와 비교 | 확인한 메타데이터 필드, 일치/불일치, 미확인 사항 |
| 4. 알림 | 기존 Telegram 전달 결과와 중복 여부를 확인하고 승인된 담당자에게 최소 범위 공유 | alert_log 참조, 전달 결과, 공유 범위 |
| 5. Containment | 부적절한 수집/노출 의심 시 source를 PAUSED로 변경하고 scheduler 재시작; 필요한 경우 운영자가 수집·전달 프로세스를 중지 | 중지 범위, 수동 승인, 설정 변경 기록 |
| 6. Evidence preservation | event_key, UTC 시각, 제한된 history/alert 기록, 최소 범위 ELK query/export를 접근 제한 위치에 보존 | 추출 시각, 조건, 파일 해시, 접근 담당자 |
| 7. Escalation | 한국 관련 CRITICAL/HIGH는 담당자 검토·상위 보고 대상으로 우선 전달하는 예시 적용 | 확인 수준, 관련성 근거, 보고 대상·시각 |
| 8. Recovery | 원인 수정, 비밀정보가 노출됐다면 담당자가 회전·폐기 검토, offline 테스트 및 read-only 점검 후 단계적 재개 | 수정 사항, 테스트 결과, 재개 승인 |
| 9. Post-incident review | 탐지/대응 시간, 오탐, 노출 범위, 보유기간·접근권한·source 상태를 재검토 | 개선 과제, 담당자, 완료 조건 |

## 검증과 대응의 경계

실제 유출 파일/첨부를 내려받아 진위를 확인하거나 증거를 확보하지 않습니다.
CAPTCHA 우회, 유출 credential 재사용, 피해 시스템 로그인·스캔·접근은 절차에 포함하지 않습니다.
이 playbook은 수집 메타데이터와 조직이 이미 승인한 확인 자료 수준으로 제한합니다.

CRITICAL/HIGH 등급은 기존 heuristic의 출력이며 실제 피해·법적 위반을 확정하지 않습니다.
경찰/기관 신고가 항상 필요하다고 단정하지 않습니다. 조직 정책과 상황별 법적 판단에 따라
책임자가 외부 보고·통지 필요성, 범위, 기한을 별도로 결정합니다.

## 증적 보존과 삭제의 충돌

대응 중 보존이 필요한 metadata/history가 있다면 retention apply를 자동 실행하지 않습니다.
책임자가 보존 범위·기간·접근권한을 결정하고 기록합니다. 본 도구에는 legal-hold 예외 엔진이 없습니다.
원본·내보내기 모두 최소 필드와 최소 기간으로 다루며, 공개 저장소/메신저에 원문 export를 첨부하지 않습니다.
Git에는 실제 사건 정보 대신 합성 데이터의 재현 절차와 코드만 남깁니다.

ELK query/export에도 회사 관련 정보가 포함될 수 있습니다. 필요 없는 description, 전체 URL,
내부 전송 snapshot은 제외합니다. audit 파일의 해시 값도 익명 자료라고 단정하지 않습니다.

## 재개 전 확인

정식 Django 진입점·로그인·로그아웃·접근 차단, source registry,
필드 최소화, read-only governance 검사와 기존 회귀 결과를 확인합니다.
Day 12 전파 지연·누락 여부는 해당 연동 검증 절차로 확인합니다.
중복 전송·DB partial failure 여부를 실제 기존 이력으로 검토하며 상태 토큰을 임의로 삭제하지 않습니다.

## 사건 기록 양식

사건 참조 / 탐지 시각(UTC) / source / event_key 또는 내부 참조 / 현재 확인 수준 /
위험도와 수동 검토 결과 / 담당자 / 제한·공유 범위 / 증적 참조와 해시 /
보존·삭제 판단 / 상위 보고 여부 / 재개 조건 / 후속 과제.

실제 자격증명, 원문 파일, raw HTML, 원문 예외 메시지를 위 양식에 붙여넣지 않습니다.
